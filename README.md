# nabi-plugins — 클로드 코드 플러그인 모음

클로드 코드에서 **두 줄이면 설치**된다. 폴더를 복사하거나 경로를 외울 일이 없다.

```
/plugin marketplace add <이 저장소>
/plugin install upgradeskill@nabi-plugins
```

새 판이 나오면 `/plugin marketplace update` 한 줄이면 따라온다.

---

## upgradeskill

저장소를 **멈추지 않고 재귀적으로** 개선하는 방법. 한 배치가 고리 넷을 돈다:
조사 → 개발 → 검증·배포 → **이 스킬 자신 고치기**.

넷째가 핵심이다. 같은 헛걸음을 두 번 하면 그건 스킬의 결함으로 보고 스킬을 고친다.

### 이 스킬에 담긴 것 — 겪어서 배운 규칙들

* **"없다"고 말하기 전에 세 걸음**(이름 → 낱말 → **소스**). 한 배치에서 여덟을 "없다"고
  보고 시작했는데 여섯이 이미 있었다. 다른 배치에서는 낱말 대조까지 하고도 다섯을
  잘못 짚었다 — 한쪽이 다른 쪽의 화면 문구를 **빌려 쓰고** 있었기 때문이다.
* **쌍둥이 화면을 세어 본다.** 세 배치 연속으로 이 방법이 그 배치의 재료 전부를 댔다.
  먼저 물을 것은 "무엇이 없나"가 아니라 **"둘이 같은 함수를 부르나"** 다.
* **시험을 먼저 깨 볼 것.** 통과하는 시험은 통과한다는 것만 증명한다. 이 방법으로
  아무것도 안 읽으면서 초록이던 검사기와, 안전장치를 빼도 초록이던 시험을 잡았다.
* **검사가 재는 대상과 나가는 물건이 같은가.** 한 프로젝트에서 사용자 PC 에서 아예 안
  뜨는 판이 나갔고, 뿌리 넷이 전부 이것이었다.
* **"안 배선하면 컴파일이 깨지는 모양"으로 만든다.** 새 함수는 아무도 안 불러도 조용하지만
  기존 열거형에 변종을 더하면 컴파일러가 빠진 자리를 전부 짚어 준다.

### 방법과 값을 갈라 두었다

스킬에는 **방법**만 있다. 게이트 명령·배포 절차·정체성 같은 **값**은 저장소의
`.claude/upgrade-project.md` 에서 읽는다. 처음 쓰는 저장소에서는 스킬이 빌드 파일·CI
설정·README 를 훑어 그 파일을 **스스로 만들고**, 모르는 것만 묻는다.

갈라 둔 까닭은 하나다. 값을 스킬에 박아 두면 **다른 저장소에서 엉뚱한 명령을 실행한다.**
이 스킬의 원본에는 특정 프로젝트의 릴리스 절차와 저장소 이름이 60곳 들어 있었다.

### 쓰는 법

```
/upgradeskill
```

배치 하나가 돌고, 끝나면 **묻지 않고 다음 배치를 연다.** 되풀이하려면
`/loop 1h /upgradeskill` 처럼 걸어 둔다.

## 직접 손보기

```bash
git clone <이 저장소> && cd nabi-claude-plugins
claude plugin validate ./plugins/upgradeskill    # 형식 검사
claude --plugin-dir ./plugins/upgradeskill       # 설치 없이 그 자리에서 시험
```

고친 뒤 `/reload-plugins` 하면 다시 띄우지 않아도 반영된다.
